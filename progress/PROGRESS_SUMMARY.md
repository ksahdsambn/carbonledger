## 三、本次会话修复的缺陷（均由真机取证驱动）

1. **线上全流程全部失败** → 根因：Gemini Key 所属 AI Studio 默认项目月度支出上限用尽（HTTP 429）。处置：在部署项目（已绑定结算）新建仅限 `generativelanguage.googleapis.com` 的 Key，运行时注入；仓库仍零密钥。
2. **单次全流程 412s（目标 ≤180s）** → 根因：每条记录两次全量因子列表（743 条 × 3072 维向量 ≈18MB），且 Firestore 与 Cloud Run 跨区。处置：因子库按 store 记忆化（索引构建 5s→4ms）+ 单据有界并发（默认 4，结果按单据顺序回并保证可复现）。**412s → 61.3s**。
3. **单据永久停留非终态（19/20 卡死）** → 根因：`withStatus` 对 `ERR_ENUM_INVALID` 不标记 failed，而模型校验失败同码。处置：任何处理失败均标记 failed；单条记录失败不再拖垮整份单据；报告叙事失败回退确定性模板。
4. **报告与台账不一致（T-050 验收 A5 失败）** → 根因：**报告生成非单飞**，懒生成路径与流水线自身装配并发，可能基于半写入台账出报告（同一任务两份报告、间隔 29ms）。处置：每任务一份确定性报告文档 + 在跑任务跟踪，`GET /report` 先等待在跑任务。**修复后 13/13 任务报告与台账完全一致**。
5. **匿名认证未真正落地** → 启用 Anonymous 提供方；前端进入即匿名登录（会话持久化 + 静默续期）；后端用 firebase-admin 校验 ID token 并以其 uid 作为任务 owner，客户端自填头不再可信（NFR-301 伪造头被拒）。
6. **单模型策略未在代码层强制** → 新增 `AI_MODEL_ALLOWLIST`（默认仅 `gemini-3.5-flash-lite` + `gemini-embedding-001`），真实调用前校验，其他模型直接拒绝且不发请求。
